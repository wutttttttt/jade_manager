# 开发路线图、MVP 与验收

日期：2026-09-23。客户和商家第一阶段均采用 uni-app + Vue 3 + TypeScript 构建微信小程序；服务端为 TypeScript 单体应用，使用 PostgreSQL。商家端以后从同一业务代码扩展 App，端能力通过替换接口接入。用户已批准由计划任务开始搭建。

## 1. 三个不同的完成点

- **首次可运行闭环 T1**：用合成数据跑通“录货及三项价格 → 审核 → 客户系数 → 发布 → 公开/客户看款与询价”。客户身份先用隔离开发测试入口验证权限。
- **私域试用 T2**：真实小程序手机号授权、商品可见分组、单客商品授权、客户系数与关键弱网能力通过验收，并具备审核、隐私、导出和恢复保护后，才能给少量档口使用。
- **完整 MVP T3**：在 T2 上补齐 F-1 至 F-13 的本期最低能力及相应验收。盘点和应收延后于首次运行，但仍在本期，不被排除。

## 2. T0：确认与工程基线（优先级最高）

**输入**：现有文档、用户确认的微信入口、合成货品与报价样例。

**顺序**：

1. 按已确认技术栈创建最小工程、锁定兼容版本；不创建 App 工程或标签系统。
2. 实现客户系数和按元展示；按 D-05 固定权限项实现老板配置。
3. 按原文 P0 开展 Q-1 等访谈；商业验证可与技术样例并行，但必须在扩大投入前形成结论。
4. 按所选栈创建最小工程、真实依赖清单与锁文件、配置示例、初始化/迁移、合成种子、启动和关键检查命令；更新环境文档。

**验收**：新终端能按文档安装固定版本、初始化空数据、启动最小应用，看到明确就绪状态；无密钥进仓库；测试身份仅在开发环境有效。此时还不能判业务闭环通过。

## 3. T1：首次跑通的最小路径

按以下顺序实现，不先做大后台或完整报表：

| 步骤 | 模块与最小能力 | 可观察的验收标准 |
|---|---|---|
| 1 | B/O：档口、老板/伙计、会话、可配置权限、审计基础 | 两个合成档口相互不可读取数据；新增伙计默认无权限；老板授权后只能获得指定能力；员工不能自提权 |
| 2 | G/M：货号、基础属性、证书来源、图片与视频、审核状态 | 建一件货可保存并重新打开；编号唯一；图片与视频都可展示；未审/被拒媒体在客户入口及直接媒体请求中均不可访问 |
| 3 | C/P/S：多个商品组、单客商品授权、三项价格、客户系数、单客价格修正 | 分组只改变商品集合；单客商品授权使组外客户可见；客户系数只改变价格；单客价格修正优先且数字价不低于最低价 |
| 4 | S：批次草稿、选货、发布、复用入口、历史记录 | 一次选择多件发布成同一批次；重试不重复发布；重启后批次和成员仍在；过往批次可查 |
| 5 | 客户与商家微信小程序界面 + S/P/M/端能力 | 商家可用小程序录货和发布；访客可看商家名片与无门槛商品；测试客户可看客户系数价并联系老板；相机/视频调用通过端能力接口；模拟身份有明确标记 |
| 6 | G/S：最小状态与撤销联动 | 在库货改为不可售或撤销可见性后，旧入口刷新不可继续获取该货的有效报价/媒体；并发旧版本改动明确失败 |

**T1 合成验收数据**：两个档口；每档口至少两个商品组；一个客户同时属于两个商品组并设置客户系数，另一个客户只属一组并额外获一件组外商品授权；包含无系数和访客场景。商品包含三项价格、无门槛开关、公开价格开关及可见组。

**T1 必过检查**：跑通上述六步；检查列表/详情/筛选/媒体/导出入口没有字段越权；断网重试不重复发布；重启后持久化数据还在；同版本两次冲突写入只能有一次成功。具体测试命令与输出应写入进度文件。

## 4. T2：私域种子试用

**进入条件**：T1 通过；D-02/03/05/06/07/10 的相关真实试点条件得到确认；目标档口愿意按当前防外泄边界使用。

**新增能力与影响**：

- B/C/S：真实微信登录、手机号授权、商家管理商品组、单客商品授权和客户系数；替换测试身份并关闭生产测试入口。核验个人主体 AppID 的实际能力和发布条件。
- P：完善单客商品修正、未授权/未设置客户系数策略和权限化价格字段；接口只返回当前客户有效价，不让界面增加价格计算分支。
- G/M/S：手机录货、离线草稿和补发、语音等低门槛录入路径、媒体体积控制、按需播放、审核处置和追溯标识；记录真实成本样本。
- C/O：跟进记录、完整客户归属、老板数据导出、员工停用、备份恢复和运行观测；完善隐私告知及数据处理流程。
- S：打开/询价留痕、关注档口留痕、历史批次和现价说明；分发在自有渠道人工完成，不擅自增加主动群发。

**验收**：

1. 两个真实测试微信账号分别配置商品组和客户系数：不同组看到不同商品；同时属于两组时取商品并集且不重复；单客授权可显示组外商品，撤销后回到公开/分组规则；相同商品按客户系数显示不同价。转发入口不能改变接收者权限。
2. 使用 [报价样例](03-data-and-interfaces.md#2-价格算法与一致性) 检查挂牌价、客户系数、单客修正、最低价兜底及无数字价；修改系数后刷新立即生效；隐藏货品同时隐藏价格。
3. 手机断网保存草稿，关闭再打开仍可找回（在明确支持的设备范围内）；恢复联网只发布一次；无法持久保存时明确提示失败。语音输入在实际设备验证，不能把“键盘可能支持”当成通过。
4. 拒绝审核和撤回审核后所有外部访问路径拒绝；媒体不自动批量加载视频；测得存储、展示流量与审核/接口费用，结合预算决定 D-10 上限。
5. 停用伙计后现有会话失效，档口客户/货品/跟进仍完整；伙计不可完整导出客户，老板可导出并检查完整性；完成一次数据与媒体联合恢复演练。
6. 老板现场确认一次发布后的分发操作减少、愿意上线新款；客户无需额外安装或自建账号注册，授权及等待商家设置商品组/客户系数的过程可接受。A-1/A-2/A-3 未通过时须记录原因。

## 5. T3：完整 MVP，补齐本期经营闭环

**新增与影响**：G 完整状态与借还、证书人工查验、组合筛选、自有/寄售归属；I 人工盘点和差异复核；R 线下应收、核销、账龄、对账单；B/O 扩展财务权限及关键操作审计。不得把应收模块变成在线支付或完整进销存。

| 验收组 | 最低可操作标准 | 对应原文 |
|---|---|---|
| 货档与找货 | 按编号或扫码定位（使用已确认载体的扫码能力，无专用硬件）；记录器型相应尺寸/重量、证书与来源、归属、存放位置；组合条件能定位样例货 | F-5/7、A-4 |
| 状态与责任 | 所有原文状态各有经确认的进出规则；一次借出有且仅有一次有效归还；超期可见、未还可导出；失败和并发不产生半条流转 | F-6/10、A-4/6 |
| 盘点 | 发起范围盘点并输入实盘，重复录入不重复计数；有期间移动的差异单独复核；每条差异有时间与责任记录 | F-8 |
| 应收 | 示例应收 10,000 分，收 4,000 分核销后余 6,000 分；重复提交不会再次扣减；超额核销拒绝；冲销可追溯；按客户/账龄汇总与流水相符 | F-9 |
| 对账交付 | 按客户与截止日生成可读、可导出的对账单，交由老板发送并留交付记录；具体文件格式和交付体验待选型/样例确认 | F-9 |
| 价格与协作 | 老板可分别配置员工查看/编辑挂牌价、成本价、最低价、客户系数和单客修正的权限；员工只在授权范围报价且不能自提权；客户数字价不低于最低价 | F-13、A-7 |
| 数据与复现 | 干净终端按 README 和环境文档独立启动；恢复备份后客户、货物、媒体、账目和审计可对应；无生产密钥或真实数据提交 | C-2/5、用户复现要求 |

**完整 MVP 完成条件**：F-1 至 F-13 逐项有验收记录；A-1 至 A-7 有场景证据；安全/权限/备份等硬性要求通过；尚未确认的 M 指标不能标记“已达标”。Q-6 可能改变 T3 内的投入先后，但删除必须功能需要另行确认范围。

## 6. T4：验证与后续扩展（完整 MVP 后）

| 顺序 | 新增或优化能力 | 对现有模块的影响 | 开始条件 |
|---|---|---|---|
| 高 | 结合种子数据优化录货、分发和看款步骤；验证留存/付费 | 主要调整两类界面与 S/C，复用原有授权/报价接口 | Q-1/2/3/9/14 有真实样本；不因优化绕过价格隔离 |
| 高 | 按真实视频量和访问量优化内容成本、稳定性与恢复 | M/O 为主；只有测量表明必要才增加处理机制，需另行技术决策 | D-10/17 与 M-6 上限确定，有成本/时延观测 |
| 中 | 经授权的证书查验、有限提醒 | G 增加查验结果与来源，S/G 增加授权与发送结果记录 | 官方能力与权限确认；仍不作鉴定结论、不承诺无限主动消息 |
| 中 | 根据实测完善寄售/借货协作 | G/C/B 扩展对象和授权范围 | Q-7 明确；引入外部角色前做独立权限设计，不涉及分账 |
| 低 | 新市场、新品类、平台订单、硬件或其他排除能力 | 可能改变数据模型与外部依赖，不能直接并入本期接口 | 必须重写范围并获确认；E-1 至 E-12 不自动解禁 |

原文 M-2/M-3/M-4/M-5 为运营或商业目标，不是一次测试可验证的性能指标。打开比例的分母必须是可确定的实际分发对象；若手工转发无法获得可靠分母，只报告可测访问数据，不编造转化率。留存、付费与续费需经过相应时间窗口。
