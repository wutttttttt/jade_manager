# 数据规则与模块接口

日期：2026-09-23。以下规则是当前实现契约；T0/T1 已实现部分见 [当前进度](06-progress.md)，未列为通过的接口仍不是已上线能力。模块名见 [架构](02-architecture.md)。

## 1. 最小数据模型

所有业务实体具有所属档口、唯一标识、创建/更新时间；需并发更新的实体具有版本。时间统一保存为明确时区的时刻，界面按中国标准时间展示（建议，待确认）。金额建议以人民币分为整数记录；系数以精确十进制规则运算，禁止使用二进制浮点金额。技术实现随 D-01 决定。

| 实体 / 所属模块 | 核心信息与关系 | 关键约束 |
|---|---|---|
| Stall / B | 档口和数据归属 | 所有查询强制限定当前授权档口 |
| Staff、PermissionGrant / B | 员工、固定权限项、授权范围、启用状态 | 权限由老板配置；新增员工默认无权限；停用使现有会话失效；业务资产不随账号删除 |
| ViewerBinding / B | 小程序 AppID 范围内的微信身份、获授权手机号与档口 Customer 的映射；授权时间/状态 | 未建立可信映射不发专属报价；手机号不是主键；更换号码或冲突不能自动继承历史客户权限 |
| Customer、AudienceGroup、CustomerGoodsGrant / C | 客户资料、多个商品可见分组、单客商品授权、客户价格系数、跟进记录 | 商品组和单客授权与定价解耦；单客授权优先补充可见性；MVP 不建立标签模型；各档口独立定义 |
| Goods / G | 唯一货号、器型和属性、证书来源、尺寸/重量单位、位置、归属、自有/寄售 | 档口内货号不重复；历史引用存在时不能直接硬删除 |
| GoodsMovement、Loan / G | 原/新状态、责任人、对象、期限、原借出记录、版本 | 同件货不得存在两个未结束借出；归还必须指向有效借出记录；纠错保留旧记录 |
| GoodsPrice、CustomerPricing、CustomerGoodsOverride / P | 挂牌价、成本价、最低可售价；客户价格系数；单客单品修正价；价格版本 | 三项商品价格独立鉴权；修正价限定客户和货品；任何客户数字价不低于最低价；未设置价格不同于零元 |
| MediaAsset / M | 货品引用、类型、大小、源文件/展示版本、审核状态及审核人 | 审核状态至少待审/通过/拒绝/撤回；只允许通过状态外显；资产只能绑定同档口货品 |
| Batch、BatchItem、GoodsAudience / S | 批次、排序、成员、发布时刻、无门槛标记、商品组、撤销状态 | 商品可公开或属于多个商品组；草稿不可对外；可见权限收回立即生效；不保存定价规则 |
| ViewRecord / S | 批次/货品、已识别客户或匿名标记、访问/询价时刻 | 无法确认身份时不能声称“某客户看过”；保留期与隐私告知待 D-06 |
| Stocktake、Count、Difference / I | 盘点范围、截止时点账面、实盘、期间变更、复核 | 重复扫描/输入不重复计数；盘点期间发生移动需人工复核，不能静默抹平 |
| Receivable、Receipt、Allocation、Reversal / R | 客户、货品或交易说明、金额、到期日、线下收款、核销关系、冲销 | 核销总额不大于可核销余额；并发核销原子检查；禁止删除已生效流水 |
| AuditEntry / O | 操作者、档口、动作、对象、时间、关联请求、必要的变更摘要 | 敏感改价明细按权限单独存取；普通运行日志不得记录成本、令牌或完整客户资料 |

## 2. 价格算法与一致性

MVP 价格规则已由用户确认：

1. 确认调用者档口、身份及客户绑定；先计算可见性。访客只见无门槛商品；已识别客户可见“无门槛商品 + 所属全部商品组商品 + 单客商品授权”的并集。单客授权优先于组成员缺失，但不覆盖下架、审核拒绝或停用等全局禁用状态。商品组和单客授权均不参与价格计算。
2. 商品保存三个相互独立的基准：挂牌价、成本价、最低可售价。挂牌价用于对外标价和客户系数计算；成本价仅授权角色可见并供记账；最低可售价是客户数字展示价的硬底线。
3. 已识别客户存在有效的单客单品修正价时，以该值为候选价；否则客户有商家设置的价格系数且挂牌价可用时，以 `挂牌价 × 客户系数` 为候选价；无系数时以挂牌价为候选价。标签系统不在 MVP。
4. 最终数字展示价为 `max(最低可售价, 候选价)`。手动修正优先选择价格来源，但不能突破最低可售价。金额内部按分保存和计算，最终四舍五入到元展示。缺少挂牌价且无修正价时不显示数字价。
5. 未授权客户只能看无门槛商品。已授权但未加入商品组且没有单客商品授权的客户也只看无门槛商品；无门槛商品可由商家选择展示挂牌价或隐藏价格。
6. 客户响应仅含按元展示的最终金额、币种、展示策略与价格版本；不含成本、最低价、客户系数或计算过程。员工字段由老板配置权限，服务端逐字段校验。

员工的“指定客户上下文”也必须受获授权范围限制，不能靠任选客户编号读取客户资料或报价。权限配置只开放预定义能力和范围，不允许员工自己提升权限；老板账号和权限管理审计不能被普通员工关闭。

客户系数修改后，所有没有单客单品修正价的在售货品对后续读取同步生效；修正价不被改写。客户系数、挂牌价、最低可售价或修正价变更都立即改变后续取价。内部报价和客户报价使用同一函数。

首次实现优先实时计算，不做客户价格共享缓存。以后如需缓存，键至少包含档口、客户、货品及规则版本，并有可靠失效路径；这是测量后才考虑的工作。

历史批次保留发布记录和成员；客户打开历史入口时仍按当前授权、状态和当前价展示，并标注当前报价时间。内部可保存历史报价快照供追溯；已确认应收金额不跟随展示价变更。任何从页面抄录的旧价都不能替代当前报价校验。

示例仅用于合成测试：某商品挂牌价 20,000 分、成本价 10,000 分、最低可售价 12,000 分。普通访客在商品允许公开价格时看到 20,000 分；系数为 0.8 的客户看到 16,000 分；为该客户设置 14,000 分修正价后看到 14,000 分；修正价设为 11,000 分时最终仍显示 12,000 分。隐藏价格的无门槛商品对访客不返回数字价；受限商品对访客不可见。

系数以挂牌价为基准，不以成本价为基准。客户无需知道系数或最低价；员工是否可查看/编辑挂牌价、成本价、最低价、客户系数和修正价由老板分别授权。

## 3. 状态流转契约

说明书的在库、借出、押货、封货、预定、售出、退回、在途全部保留。首个闭环仅实现已确认的小集合，未实现状态必须明确禁止写入，不能用自由文本假装完成 F-6。

| 候选流转（待 D-08 确认） | 必填信息与保护 |
|---|---|
| 在库 → 借出 → 在库 | 借货对象、责任人、借出/应还时间；归还对应原记录；归还后位置 |
| 在库 → 封货 / 预定 → 在库或售出 | 关联客户、操作人、约定期限、解除或售出原因；封货/预定差异先确认 |
| 在库 → 押货 → 在库或售出 | 对方、责任人、期限与实际业务含义；不自动创建支付或资金保管 |
| 可发运状态 → 在途 → 目标状态 | 原状态、目的地、交接人、到达确认；在途不是丢失原业务意图 |
| 售出 → 退回 → 在库 | 原售出记录、退回原因、验收与去向；财务冲销单独处理 |

默认仅“在库”对客户可售展示；其他状态是否显示“已封/已售”待确认。非法转移、版本过期、缺少责任信息应明确失败；失败时状态和审计都不能产生半条业务结果。列表与详情读取当前状态，历史批次不能让已经不可售的货继续显得可售。

## 4. 逻辑接口清单

以下名称是模块函数/用例标识；实现时可映射为所选栈的服务方法或网络接口，不预先规定 URL。写请求需有身份上下文，金额/状态/归属在服务端校验，客户端校验仅提升体验。

| 接口 / 所属模块 | 输入 | 输出与调用方 | 关键约束 |
|---|---|---|---|
| `Authorize` / B | 当前身份、目标对象、动作 | 允许动作及字段范围；所有模块 | 默认拒绝，档口范围不能由外部参数覆盖 |
| `BindViewer` / B | 已验证身份、档口内客户匹配凭据 | 客户上下文；S/P | 绑定须经可信渠道或授权人员核验；禁止按自报手机号直接取得已有客户权限 |
| `ExchangeWeChatLogin`、`BindAuthorizedPhone` / B | 微信登录临时凭证；当前会话及手机号授权凭证 | 自有会话；已核验手机号与待设置客户 | 登录与手机号凭证分开处理；只接受服务端核验结果，不能信任客户端传入的 openid/手机号 |
| `SaveGoods` / G | 货品草稿、媒体引用、版本、请求标识 | 货号及新版本；工作台 | 重试不重复建档；不同档口引用拒绝 |
| `ChangeGoodsState` / G | 货号、期望版本、目标状态、业务信息、请求标识 | 新状态、流转记录；工作台/I 复核 | 检查转移规则、并发与事务完整性 |
| `SaveCustomerAudienceGroups`、`SetCustomerActive` / C | 客户、商品组集合、启用状态、版本 | 新可见范围版本；工作台/S | 多组按并集处理；更新立即影响商品可见性；停用后只剩访客公开集；不改变价格；审计留痕 |
| `GrantGoodsToCustomer`、`RevokeCustomerGoodsGrant` / C | 客户、商品、版本 | 单客授权状态；工作台/S | 授权可使组外客户看见该商品；撤销后重新按公开/分组规则判断；不改变价格；审计留痕 |
| `UpdateCustomerPricing` / C | 客户、价格系数、版本 | 新客户价格版本；工作台/P | 系数更新立即影响报价；不改变商品可见性；审计留痕 |
| `UpdateGoodsPrices` / P | 挂牌价、成本价、最低可售价、展示设置、期望版本 | 新价格版本；获授权员工 | 三项价格逐字段鉴权；最低价不得高于需要直接展示的挂牌价而不提示冲突 |
| `UpdateCustomerCoefficient`、`SetCustomerGoodsOverride` / P | 客户系数；客户、货品、修正价、期望版本 | 新规则版本；获授权员工 | 权限与档口归属校验；变更立即生效，失败不部分生效 |
| `GetEffectiveQuote` / P | 从身份派生的客户上下文、货号 | 该客户有效报价或面议；S/员工报价页 | 先鉴权和货品可见性，不接收可信度不足的自选客户上下文 |
| `UploadMedia`、`ReviewMedia` / M | 文件、归属、上传标识；审核结论 | 资产引用/审核状态；G/S | 大小格式校验；重试去重；审核未通过不可访问展示版本 |
| `CreateBatch`、`PublishBatch` / S | 货号集合、受众、版本、请求标识 | 批次与可复用入口；工作台 | 所有成员合法、媒体已审；发布重试不重复建批次 |
| `ListVisibleGoods`、`GetVisibleGoods` / S | 已授权身份、批次或档口、筛选/分页 | 裁剪后货品与有效价格；客户 | 列表、详情、搜索、筛选、媒体全部一致校验 |
| `OpenMedia` / M | 身份上下文、资产引用 | 允许的展示内容或拒绝；客户/员工 | 校验当前受众、货品、审核与撤销状态；禁永久公开原始地址 |
| `RecordView`、`GetContactEntry` / S | 当前访问对象与身份上下文 | 留痕、已授权的老板联系入口；客户 | 匿名标记不可伪造为客户；联系行为不自动发送消息 |
| `StartStocktake`、`RecordCount`、`ReviewDifference` / I | 范围、货号、时间、复核意见 | 快照、差异、复核记录；员工 | 不覆盖期间流转；重复录入去重 |
| `CreateReceivable`、`AllocateReceipt` / R | 客户、线下业务金额/日期、版本、请求标识 | 应收与余额；财务/老板 | 重试不重复核销，禁止超额核销；更正追加冲销 |
| `BuildStatement` / R | 客户、截止日 | 对账单及汇总；财务/老板 | 余额可复算；按授权交付，不自动发消息 |
| `ExportStallData` / O | 老板授权、范围 | 客户/货品/账目/媒体清单等导出包 | 伙计不能完整导出客户；导出留痕；媒体清单不能暴露永久公开链接 |

客户不可见资源统一返回不可访问，不区分“另一档口存在”和“不存在”；员工操作错误可区分无权限、状态冲突、输入缺失、媒体未审、版本过期，便于纠正。具体错误编码在技术栈确认后固定。

## 5. 可靠性、弱网与安全验收边界

- 每次重要写入接受唯一请求标识；同身份同档口同请求重试返回原结果，不重复发布、借出或核销。相同标识配不同内容应拒绝。
- 离线只保存录货草稿、拍摄素材和上传任务；不保存其他客户的价格、不预先确认出库、发布或核销。重新联网后校验身份与版本再提交。
- 本地草稿需明确保存成功/失败与待上传数量；设备容量不足或不支持持久保存时不得声称已保存。上传成功前不能删除唯一媒体副本；退出账号时说明并处理本地草稿归属。
- 媒体撤回后，新请求立即拒绝；任何短期下载凭据的有效期与撤销机制需实测。已下载内容不可承诺远程回收。
- 普通日志隐藏身份令牌和财务敏感字段；审计有独立访问权限。授权导出、数据删除/保留、隐私说明、内容申诉与恢复目标在 D-06 中确定。
- 针对上述真实风险编写集成检查；不为文档或简单字段访问机械生成测试。具体验收场景见 [路线图](04-roadmap.md)。

## 6. 微信小程序身份与手机号流程

**已确认的产品要求**：客户在微信小程序打开并可选择授权手机号。商家可创建多个商品可见分组，也可把单个商品直接授权给某个客户；这两种方式只决定商品可见性。MVP 由商家直接设置客户价格系数，标签功能后置。访客可看商家名片和无门槛商品。

1. 客户从档口分享入口进入小程序。入口只指定档口/批次，不携带可被直接信任的客户编号、组别或专属价格。
2. 小程序获取微信登录临时凭证，服务端核验并取得该小程序范围的身份标识，建立本系统会话。不能信任客户端自报的 `openid`，也不能将 `openid` 单独作为可重放的登录凭证。
3. 界面说明手机号用于档口识别与分组报价；客户主动触发并同意授权后，服务端使用手机号授权凭证获取号码。登录凭证与手机号授权凭证分别处理，不互相替代。禁止设计为打开页面即静默读取号码。
4. 服务端将核验号码关联到微信身份及档口客户。商家在“待设置客户”中选择零个或多个商品组并设置客户价格系数；也可从商品页直接选择客户建立单客商品授权。号码相同只能作为候选匹配，不能自动继承旧权限。
5. 未授权客户可看名片和无门槛商品；已授权但未进商品组也不自动获得受限商品。商品组、单客授权或客户系数变更后刷新立即生效，无需重新注册。
6. 拒绝授权、授权失败、会话过期均提供重试或联系老板入口，不建立虚假客户绑定；不返回其他客户报价或内部客户详情。技术失败不得降级为公开价表。
7. 更换手机号、号码被多个微信身份使用、旧号码重新分配、客户档案合并，进入商家复核流程；号码变化不自动迁移商品组、单客授权或客户系数。主体身份和档口客户记录保留审计。
8. 商家调整商品组、授予/撤销单客商品、变更客户系数或停用客户后，后续请求重新检查权限；旧分享入口不能恢复权限。同一微信用户在不同档口的商品组、单客授权和客户系数互不复用。

最小权限矩阵补充：客户仅能看自己的授权结果；员工权限由老板配置，新增员工默认无权限。核对手机号、设置商品组与单客授权、查看三项价格、编辑系数、发布、导出和权限管理分别鉴权并留审计；普通员工不能授予自己权限。

## 7. 商家端跨平台能力边界

商家端第一阶段只交付小程序，后续以同一业务代码扩展 App。这里的“同一套代码”指业务状态、校验、接口调用和可复用页面逻辑；不承诺所有平台能力零差异复用。

业务代码只依赖实际需要的窄能力契约，例如 `CapturePhoto`、`RecordVideo`、`ScanCode`、`StoreDraftFile`。小程序适配器调用小程序平台能力；App 阶段再用原生插件实现相同契约。未来接入称重、打印或专用盘点设备时，为具体设备能力新增接口，不创建一个包含所有硬件的万能接口。

第一阶段不创建 App 工程、不实现空原生插件。T1 只为已经使用的相机、视频和本地草稿能力建立接口与小程序实现，并用合成数据和实际设备验证。业务模块不得直接散落平台 API 调用，否则后续替换无法局部完成。

AppSecret、平台调用凭证和会话密钥只存服务端安全配置，不提交仓库、不放小程序包、不打印到日志。开发测试使用合成客户；真实接口失败测试不得调用他人号码。

- [微信：获取手机号](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)
- [微信：登录凭证校验](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html)

接入前由开发者使用已开通权限的主体核验：手机号能力的开通条件与费用/额度、隐私声明与授权配置、凭证生命周期及重复兑换行为、基础库兼容性、服务器域名和网络配置。当前文档不依赖任何未经核验的固定额度或免费承诺，不混用旧版加密数据解码教程。
