# 翡翠档口工具 · 项目定义与功能边界说明书

> 版本：v1.1 ｜ 编制日期：2026-09-22 ｜ 适用市场：广东揭阳阳美玉都及周边玉器市场
> 用途：供后续环节据此规划技术实现路径。本文档只界定**目的、效果与功能边界**，不含技术选型与实现方案。
> 标注约定：凡未经实地验证的内容均标为「待确认」，不得作为既定事实使用。

**v1.1 修订说明**：新增「分组与阶梯定价」能力，涉及 F-3、F-4、F-5、F-11 的相应扩展，新增 F-13、A-7、S-7、C-12 及 Q-15 至 Q-19。

## 1. 项目定位与目标

### 1.1 一句话定位

面向揭阳阳美翡翠档口老板的日常经营工具：让老板**一次发布新款，老客户点开即看全**，并顺带把非标品的货、状态与账管清楚。

### 1.2 要解决的核心问题

- **P-1 发款效率低**：老板每天多次通过即时通讯工具逐个或逐群发送新款图片与视频，重复劳动量大；已发款式难以回溯，无法知道谁看过、看了哪一件。
- **P-2 客户资产不沉淀**：客户散落在个人通讯录与聊天记录中，人员流动即造成流失，无法按群体差异化触达。
- **P-3 非标品货况不清**：翡翠一物一图一证，借出、押货、封货、寄售等状态依赖记忆与纸本，易错、易丢、易起纠纷。
- **P-4 款式外泄顾虑**：公开传播易被同行抄款，导致老板不愿把新款放到任何线上渠道——这是决定产品被采用与否的关键心理门槛。

### 1.3 目标用户

- **U-1 主要使用者与决策者**：阳美、乔南、乔西玉器市场的中小档口老板（以自有货为主，未配备独立直播机构）。
- **U-2 次级使用者**：档口伙计 / 店员（录货、发款、盘点）、财务或对账人。
- **U-3 触达对象（非付费方）**：老客户，以外地玉商、零售店主、直播选品人为主。
- **U-4 延伸角色（本期不作为主要对象，见 Q-7）**：货主（寄售方）、主播（借货方）。

### 1.4 主要使用场景

- **S-1 日常发款（最高频）**：按市场节奏一天多批次发布新款，一次操作覆盖多件，并向不同客户群体分发。
- **S-2 客户看款与询价**：老客户接收后直接查看全部新款，按条件筛选，并直接联系老板议价。
- **S-3 建货档与改状态**：新货入库建档（含证书信息），日常维护货品状态。
- **S-4 盘点与找货**：定期盘点、按特征定位货品、核对差异。
- **S-5 对账与催款**：记录应收与账期，生成对账单交付客户。
- **S-6 交接与防丢**：高值货品责任到人、操作可追溯。
- **S-7 差异化报价**：对不同等级客户给出不同价格，或由伙计在老板不在场时按既定边界报价。

## 2. 预期效果与验收标准

### 2.1 定性验收标准（完成时应可观察到的结果）

- **A-1 发款动作被合并**：老板完成一次发布即可实现对多客户的展示，不再逐个人、逐个群重复发送。
- **A-2 看款零门槛**：老客户从接收到完成查看，全程无需安装专用应用、无需注册或填写资料。
- **A-3 老板敢上新款**：可见范围与防外泄控制足以让老板放心将新款上线。
- **A-4 货况随时可答**：对"这件货在哪、谁经手、当前什么状态"能在短时间内准确回答。
- **A-5 客户资产归属档口**：客户资料与跟进记录沉淀在档口侧，人员变动不导致资产流失。
- **A-6 历史可回溯**：任意历史批次的新款、任意一件货的流转过程均可查。
- **A-7 老板不在场也能报准价**：伙计可依据系统给出的可售边界完成报价，既不越权让利，也不需每次致电老板确认。

### 2.2 定量验收指标

> 下列数值为规划期建议目标，**均为待确认**，须在实地验证（P0）后以实测数据替换后方可作为承诺指标。

- **M-1 发布批量**：单次发布可覆盖的款式数 ≥ 20 件。（建议值，待确认）
- **M-2 使用频度**：活跃档口月均发款次数 ≥ 20 次。（推导依据：当地市场公开报道称档口一天更新三批货；该频度尚未在目标人群中实测，待确认）
- **M-3 触达效果**：分发内容被打开的比例 ≥ 30%。（建议值，待确认）
- **M-4 种子期留存**：种子档口中，连续 4 周每周发款 ≥ 3 次的比例 ≥ 60%。（建议值，待确认）
- **M-5 商业验证**：付费转化率 ≥ 25%；次年续费率 ≥ 70%。（属 P2/P3 阶段指标，建议值，待确认）
- **M-6 成本约束**：单档口月均内容分发成本不超过规划上限。（上限值待 Q-5、Q-13 确认后确定）

## 3. 核心功能边界

> 每条统一字段：**目的 / 关键能力 / 完成判据**。

### 3.1 必须实现的核心功能

- **F-1 新款发布与分发**
  - 目的：解决 P-1，把重复发送合并为一次发布。
  - 关键能力：一次录入多件新款（含图片与视频）；填写基础商品信息；生成可分发的展示内容；向不同客户群体或个体分发；保留历史批次。
  - 完成判据：满足 A-1、A-6；单次发布件数满足 M-1。

- **F-2 客户侧看款与询价入口**
  - 目的：让老客户以最低门槛完成看款并进入议价。
  - 关键能力：免安装、免注册即可查看；按档口浏览全部在售新款；按条件筛选；一键联系老板；可对关注档口留痕。
  - 完成判据：满足 A-2；打开比例满足 M-3。

- **F-3 可见范围与防外泄控制**
  - 目的：解决 P-4，消除老板上线新款的心理障碍。
  - 关键能力：按客户群体设定可见范围；展示内容可携带可溯源标识；限制内容被二次传播；记录访问痕迹；**价格属于受控信息，可见范围控制需覆盖价格本身，而非仅覆盖款式**。
  - 完成判据：满足 A-3；在种子用户访谈中确认老板愿意将当季新款上线（待确认）；不同分组的客户之间无法看到彼此的价格（关联 C-12）。

- **F-4 客户档案与分组**
  - 目的：解决 P-2，把客户资产沉淀到档口侧。
  - 关键能力：客户建档；分组与标签；跟进与拿货记录；按群体差异化分发；**分组结果是差异化定价的依据（见 F-13）**。
  - 完成判据：满足 A-5；人员变动后客户资料与跟进记录可完整承接；分组可被定价与可见范围两处复用。

- **F-5 货品档案（一物一档）**
  - 目的：为每一件非标品建立唯一档案，支撑后续所有管理能力。
  - 关键能力：唯一编号；证书信息绑定与查验；器型、种、水、色、地、工、瑕等属性记录；尺寸与重量按器型差异记录；**成本价、各档售价与最低可售价分开维护**；成本价与售价分开且受权限控制；媒体资产（图片、视频）挂载。
  - 完成判据：任意一件货可通过编号或扫码调出完整档案；属性字段配置符合当地行业习惯（待 Q-6 确认）；**同一件货可按分组带出不同价格**。

- **F-6 货品状态管理**
  - 目的：解决 P-3 的核心，让货况随时可查。
  - 关键能力：状态覆盖在库、借出、押货、封货（客户预留未付款）、预定、售出、退回、在途；状态变更留痕；借出与归还配对；超期提醒。
  - 完成判据：满足 A-4；借出未还清单可随时导出核对。

- **F-7 查找与筛选**
  - 目的：在多件非标品中快速定位目标货品。
  - 关键能力：按器型、种水色、尺寸区间、价格区间、证书、状态、存放位置、归属等条件组合检索。
  - 完成判据：常用找货场景可在数步操作内完成（具体时限待确认）。

- **F-8 盘点与差异核对**
  - 目的：支撑 S-4，降低高值货品丢失与账实不符风险。
  - 关键能力：发起盘点；账面与实际比对；差异列表；盘点结果留痕与责任归属。
  - 完成判据：差异可逐条追溯到经手人与时间。

- **F-9 应收与对账**
  - 目的：支撑 S-5，缩短对账周期、降低坏账。
  - 关键能力：应收记录与账期；按客户生成对账单并交付客户；收款核销；欠款账龄视图。
  - 完成判据：可一键生成并交付对账单；欠款按客户与账龄可查。

- **F-10 权属与责任**
  - 目的：区分"自有"与"代管"，保护成本信息，明确责任。
  - 关键能力：区分自有货与寄售货并绑定归属方；成本价仅对授权角色可见；关键操作（改价、出库、状态变更）留痕。
  - 完成判据：非授权角色无法获知成本价；任一关键操作可追溯到人与时间。

- **F-11 多角色与权限**
  - 目的：支撑老板、伙计、财务协同，同时防止客户资产被带走。
  - 关键能力：角色划分与权限配置；数据可见范围按角色隔离；**价格可见范围按角色隔离（成本价、各档售价、最低可售价的可见性分别控制）**；账号停用后数据保留在档口侧。
  - 完成判据：伙计角色无法导出完整客户资料；账号停用后客户与货品数据完整保留；**非授权角色无法获知成本价与其他分组的价格**。

- **F-12 内容资产管理**
  - 目的：支撑 S-1 与 A-6，同时控制分发成本。
  - 关键能力：图片与视频的上传、存储、展示与历史调阅；展示侧按需加载；历史内容可长期保留且成本可控。
  - 完成判据：满足 A-6；单档口月均分发成本满足 M-6。

- **F-13 分组与阶梯定价**
  - 目的：支撑 S-7。让老板按客户等级差异化报价，无需每次口述；同时让伙计在老板不在场时也有明确的报价边界。
  - 关键能力：
    - 客户分组与等级定义（分组结果直接作为定价依据）；
    - 每个分组绑定一个价格层级，或绑定一个基于成本价的加价系数，由系统推导该组价格；
    - 单件货支持按档位维护多档价格，也支持由成本价加系数自动生成；
    - 客户查看时，按其所属分组展示对应价格；
    - 未分组客户与陌生访客的价格策略可配置（不展示价格 / 展示零售价 / 展示面议）；
    - 允许对特定客户就单件货设定独立报价，覆盖其分组价；
    - 价格与可见范围联动——某分组看不到某件货时，也看不到其价格；
    - 成本价与最低可售价分权控制：伙计可见可售下限，不可见成本价。
  - 完成判据：不同分组客户查看同一件货时呈现不同价格；调整某一分组的加价系数后，在售货品对该组的价格同步生效；非授权角色无法获知成本价与其他分组价格（关联 C-12、A-7）。

### 3.2 本期明确排除项

> 每条统一字段：**排除内容 / 排除理由 / 本期替代做法**。

- **E-1 在线交易、收款与资金结算**
  - 排除理由：无支付资质主体归集交易资金并二次结算属于监管明令禁止行为，处罚与关停风险极高。
  - 本期替代：交易与收款完全由档口与客户自行完成，产品只做展示与询价承接，不触碰资金。
  - 边界澄清：**展示价格（含 F-13 的分组阶梯定价）属于展示环节，仍在本期范围内**；只有收款、担保、结算才被排除。

- **E-2 鉴定、保真、质检与质量背书**
  - 排除理由：行业真伪争议高发，一旦被理解为对货品品质背书，单次纠纷即可能造成品牌与信任崩塌。
  - 本期替代：证书信息仅作如实展示并标注来源，产品定位为档口自用展示工具，不提供任何品质结论。

- **E-3 面向终端消费者的公域流量池与商城**
  - 排除理由：批发生意的增量买家是外地二批商、零售店主与直播选品人，本地普通消费者对档口无转化价值。
  - 本期替代：触达只面向档口自有老客户与已知采购方；面向新客的分发放到后续阶段。

- **E-4 直播平台订单同步、主播与货主分账**
  - 排除理由：该场景已被市场在位者占据，且依赖平台官方授权，本期不具备条件。
  - 本期替代：如涉及借货与寄售，仅做留痕与状态追踪，不做分账计算。

- **E-5 硬件设备集成**（专用盘点设备、称重设备、打印设备）
  - 排除理由：依赖硬件采购与现场部署，投入与周期不匹配本期目标。
  - 本期替代：盘点与找货以人工操作完成，保留后续接入空间。

- **E-6 原石与毛料全链路管理**（场口、皮壳表现、合伙股份、切割过程）
  - 排除理由：与成品档口是两套业务逻辑，同时做会稀释资源。是否纳入取决于 Q-7。
  - 本期替代：本期聚焦成品；毛料场景待确认后另立范围。

- **E-7 跨市场与跨城市复制**
  - 排除理由：本期需在同一市场内跑通模式，过早铺开会导致产品与运营两头不实。
  - 本期替代：只服务阳美及周边玉器市场。

- **E-8 撮合交易、竞价排名、广告投放**
  - 排除理由：依赖双边规模，属后续阶段能力。
  - 本期替代：不涉及。

- **E-9 供应链金融与信用服务**
  - 排除理由：需长期真实经营数据积累与持牌合作方，远期事项。
  - 本期替代：不涉及。

- **E-10 门店零售收银与完整进销存**
  - 排除理由：目标场景是档口批发，不是门店零售；完整进销存是与在位者正面竞争的领域。
  - 本期替代：只做与发款、货况、对账直接相关的管理能力。

- **E-11 向外部内容平台的一键分发与代运营投放**
  - 排除理由：涉及平台授权与内容合规责任，本期不具备条件。是否纳入取决于 Q-11。
  - 本期替代：内容分发限定在档口自有渠道内。

- **E-12 智能估价与自动品质判定**
  - 排除理由：种水色在行业内无统一强制标准，自动判定易被判为外行，损害专业信任。
  - 本期替代：属性由档口按其自身口径填写，产品不输出结论。

## 4. 关键约束与前提

> 每条统一字段：**约束内容 / 影响 / 刚性**。

- **C-1 不得归集与二次结算交易资金**
  - 影响：决定 E-1 排除，产品边界止于展示与询价。
  - 刚性：不可协商（法律与监管红线）。

- **C-2 经营资质与数据合规**
  - 影响：需完成经营主体、域名与备案、隐私告知与授权、数据留存与备份；向档口提供数据导出能力。
  - 刚性：不可协商。

- **C-3 上传内容需经安全审核**
  - 影响：需建立内容审核机制与违规处置流程，否则承载载体存在被下架风险。
  - 刚性：不可协商。

- **C-4 主动触达能力受外部平台规则限制**
  - 影响：不能将产品设计为无限次主动群发；触达只能依托"分发 + 有限次服务通知 + 即时通讯"的组合，且需在有限额度内设计。
  - 刚性：不可协商（外部规则，非设计选择）。

- **C-5 数据主权与不竞争承诺**
  - 影响：必须书面承诺不自营同类业务、不转售客户数据、不主动联系档口客户，并提供一键导出。
  - 刚性：不可协商（是获取档口信任的前提，而非加分项）。

- **C-6 视频是主要内容形态，分发成本随规模线性增长**
  - 影响：内容体积必须受控，展示侧需按需加载，否则成本将吞没毛利。
  - 刚性：不可协商（商业可持续性前提）。

- **C-7 市场经营节奏为全天候、多批次**
  - 影响：能力需覆盖早市、午市、夜市多个时段，可用性与支持响应需匹配该节奏；"批次"应作为一等概念。
  - 刚性：已核实的客观事实（当地市场公开报道）。

- **C-8 使用环境受限**
  - 影响：现场网络条件不稳定、以手机操作为主、使用者以手工录入为主且输入效率有限，因此录入步骤必须极简、支持离线暂存与补发、支持语音等低门槛输入方式。
  - 刚性：高（部分细节为推断，待 Q-2、Q-5 确认）。

- **C-9 资源有限，本期只做一个市场一个品类**
  - 影响：范围收窄至阳美成品翡翠档口，排除 E-6、E-7。
  - 刚性：本期规划假设（非外部约束，可随资源变化调整）。

- **C-10 存在已占据市场首位的垂直在位者，且其已具备面向下游的选品展示能力**
  - 影响：本期必须错位——避开其在直播机构、供货中心、毛料与跨平台订单场景的主场；差异化只能建立在"中小档口的私域内容化触达"上（货架形态与内容形态之别）。
  - 刚性：不可协商（战略前提）。

- **C-12 价格信息必须按分组严格隔离，且与线下报价保持一致**
  - 影响：客户一旦发现他人拿到更低价格，会直接损害信任关系并引发流失，其后果比款式外泄更即时；同时线上线下报价不一致会导致档口内部混乱。因此价格隔离是 F-3、F-13 的硬性要求，报价口径需有唯一来源。
  - 刚性：不可协商（客户关系与信任底线）。

- **C-11 目标用户是尚未使用任何管理系统的中小档口**
  - 影响：整个项目成立的前提假设。若实地验证发现目标档口已普遍使用在位者产品且满意度高，则项目定位需重新评估。
  - 刚性：前提假设，须由 Q-1 验证。

## 5. 待确认事项

> 每条统一字段：**问题 / 为什么重要 / 确认方式 / 当前初步判断（均为待确认，非结论）**。

- **Q-1 在位者在本地市场的实际渗透率与使用者满意度**
  - 为什么重要：直接决定市场是否还有空档，是项目能否成立的第一判据（关联 C-11）。
  - 确认方式：实地走访不少于 100 家档口，逐户询问在用系统与满意度。
  - 初步判断：在位者公布的合作商户数量覆盖多个产业带与多个品类，摊到本地单一市场的密度可能有限（推断，待验证）。

- **Q-2 目标档口当前的发款方式与频次**
  - 为什么重要：决定 F-1 的形态与 M-2 的目标值。
  - 确认方式：实地观察与访谈，记录一天几批、每批几件、发给谁、用什么工具、耗时多少。
  - 初步判断：当地市场公开报道称档口一天更新三批货，频次应显著高于一般零售场景（待实测）。

- **Q-3 付费意愿与可接受价格区间**
  - 为什么重要：决定商业模式是否成立。
  - 确认方式：访谈中直接询问现有支出与可接受预算；小样本付费测试。
  - 初步判断：在位者公开年费在数千至万余元区间，说明该市场存在付费习惯（旁证，待本地验证）。

- **Q-4 防抄款顾虑的强度与可接受的可见范围控制方式**
  - 为什么重要：决定 F-3 的设计强度，是采用与否的门槛。
  - 确认方式：访谈中询问是否曾因公开新款受损、可接受哪些控制手段。
  - 初步判断：非标、高值、款式即竞争力的属性下，该顾虑应普遍存在（推断，待验证）。

- **Q-5 视频是否为必需、拍摄习惯与时长**
  - 为什么重要：决定 F-12 的成本模型与 M-6 上限，也决定 C-6 的严苛程度。
  - 确认方式：访谈与现场观察，记录拍摄设备、单件时长、每日产出量。
  - 初步判断：翡翠品质判断高度依赖动态光影表现，视频应为必需（旁证，待本地验证）。

- **Q-6 库存痛点的优先级排序**
  - 为什么重要：决定 F-5 至 F-9 的投入顺序。
  - 确认方式：就"借出未还、证书管理、封货、改款、成本保密、瑕疵记录"逐项请档口排序。
  - 初步判断：借出未还与状态混淆可能是最高频痛点（推断，待验证）。

- **Q-7 是否需要支持货主寄售与主播借货**
  - 为什么重要：决定 F-10 的范围与是否引入 U-4 角色。
  - 确认方式：访谈中统计存在寄售或对外借货的档口占比。
  - 初步判断：当地直播业态发达，借货场景应有一定比例（旁证，待验证）。

- **Q-8 老板端是否接受额外安装专用应用**
  - 为什么重要：影响重度操作（批量拍摄、离线盘点）与主动提醒能力的上限。
  - 确认方式：访谈中询问是否愿意为管理工具安装应用，以及可接受的安装前提（如是否需上门协助）。
  - 初步判断：老板侧为单人单店的高频重度使用，且可上门服务，接受度可能高于一般消费者场景（推断，待验证）。

- **Q-9 老客户的实际构成与看款习惯**
  - 为什么重要：决定 F-2 的形态与 E-3 的排除是否成立。
  - 确认方式：向档口询问其客户构成比例，并访谈若干老客户。
  - 初步判断：以异地二批商、零售店主、直播选品人为主（推断，待验证）。

- **Q-10 市场管理方的合作意愿与限制条件**
  - 为什么重要：是批量获客的潜在杠杆，也可能带来排他或品牌弱化风险。
  - 确认方式：拜访市场运营方与管委会，试探合作形式与条件。
  - 初步判断：存在合作可能，但需保留自有品牌与数据主权（推断，待验证）。

- **Q-11 证书数据的可得性与查验方式**
  - 为什么重要：决定 F-5 中证书能力能做到录入留存还是可在线查验。
  - 确认方式：向检测机构与市场方咨询数据开放程度与对接条件。
  - 初步判断：本地市场配套检测服务，存在数据对接可能（旁证，待确认）。

- **Q-12 系统可用与人工支持的时段要求**
  - 为什么重要：决定可用性目标与支持排班（关联 C-7）。
  - 确认方式：记录市场实际活跃时段与档口作业时间。
  - 初步判断：存在夜间与凌晨时段活跃的可能（推断，待验证）。

- **Q-13 单档口货品规模与内容产出量级**
  - 为什么重要：决定存储与分发成本的规划上限（关联 M-6）。
  - 确认方式：访谈中统计在库件数、月新增件数、单件图片与视频数量。
  - 初步判断：尚无依据，须实测后确定。

- **Q-15 档口实际的定价方式**
  - 为什么重要：决定 F-13 采用"成本价加系数推导"还是"每档维护固定价格"，两者的录入工作量差别很大。
  - 确认方式：访谈中请老板现场演示一件货从成本到各档报价的推导过程。
  - 初步判断：行业内普遍以成本加成为基础，同时存在标价虚高、实际成交靠议价的习惯（推断，待验证）。

- **Q-16 是否需要支持对单件货、单个客户的独立报价**
  - 为什么重要：决定 F-13 是否要引入覆盖分组价的例外机制，这是复杂度的主要来源。
  - 确认方式：询问老板是否存在"某件货对某个老客户特殊让价"的情况及其频率。
  - 初步判断：翡翠以议价成交为主，独立报价应常见（推断，待验证）。

- **Q-17 价格档位的数量与命名习惯**
  - 为什么重要：决定分组与价格层级的模型粒度。
  - 确认方式：收集档口对客户等级的实际叫法与对应加价幅度。
  - 初步判断：可能存在零售价、批发价、伙计价等若干固定档位（推断，待验证）。

- **Q-18 伙计可见的价格边界**
  - 为什么重要：直接决定 A-7 能否成立——若伙计看不到任何参考价，则老板不在场时仍无法报价。
  - 确认方式：询问老板允许伙计看到成本价、最低可售价，还是只能看到该客户的分组价。
  - 初步判断：成本价通常保密，但"最低可售价"可能需要对伙计开放（推断，待验证）。

- **Q-19 未分组客户与陌生访客的默认价格策略**
  - 为什么重要：决定 F-13 的默认分支，也影响防抄款与价格外泄的实际效果。
  - 确认方式：询问老板对新客户、陌生访客通常报什么价，是否愿意公开显示价格。
  - 初步判断：对陌生访客可能倾向于不显示价格或显示面议（推断，待验证）。

- **Q-14 免费使用与付费触发的分界点**
  - 为什么重要：决定转化机制与定价结构。分组与阶梯定价能力本身可能是付费触发点之一（关联 Q-17）。
  - 确认方式：在种子用户中做容量梯度测试，观察升级触发点。
  - 初步判断：以容量（客户数、货品数）作为分界可能优于以时间作为分界（推断，待验证）。
