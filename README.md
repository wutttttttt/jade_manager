# 翡翠档口经营工具

面向揭阳阳美及周边中小翡翠档口的本地开发基线。当前已建立并实际跑通 uni-app + Vue 3 + TypeScript 微信小程序构建、Node.js TypeScript 单体服务、PostgreSQL 16 结构与合成种子；T0 本机验收通过。T1 已补全媒体上传/审核和客户管理代码，最新数据库迁移与扩展集成场景待重启 API 后实跑；真实 AppID 和真机联调尚未完成。

## 已实现

- 一套小程序工程包含客户看款页与商家快速录货页，没有 App 工程、标签系统、空原生插件或硬件代码。
- 服务端统一执行商品可见性与报价：公开商品、多个商品组、单客商品授权取并集；分组和单客授权不参与定价。
- 报价顺序为“单客单品价 → 挂牌价 × 客户系数 → 挂牌价”，随后以最低可售价兜底并四舍五入到元。
- 客户响应只返回最终元价、币种、展示方式和组合版本，不暴露成本、最低价、系数或命中哪条定价规则。
- PostgreSQL 原生约束隔离档口数据，包含固定员工权限、媒体审核、批次、审计、幂等请求和乐观版本更新。
- 商家端可选择多件货保存批次草稿、查看批次历史，并在所有媒体审核通过后发布和转发批次入口；可撤销或恢复货品，旧批次刷新后立即按新状态变化。批次只筛选成员，打开时仍按当前权限、状态和价格计算。录货失败后重开可恢复草稿并沿用原幂等键重试。
- 商家端可上传最大 20MB 的 JPEG/PNG/WebP/MP4，按待审、通过、驳回、撤回流转；未通过媒体无法从客户入口读取。
- 小程序选择及上传媒体时按文件签名识别类型，临时路径没有扩展名或旧草稿中的类型记录有误时也能正确上传 PNG/WebP；空文件和不支持的格式会在保存草稿前提示。
- 媒体临时写入失败会清理 `.part`，原子改名在数据库事务提交前完成；落盘失败会回滚记录，同一幂等请求重试仍会完成落盘。
- 录货可保存器型、颜色和可选证书来源；本机草稿、商家重开与客户看款使用同一份持久化数据。
- 商家端可新建商品组、配置商品组归属、编辑客户多组/单客补充授权、客户系数和单客商品价，也可停用/恢复客户专属看款；可见性与定价不互相推导。
- 客户看款页重新显示时会读取当前可见范围和报价；快速切换测试身份时只采用最后一次请求的结果，已停用的测试客户会看到访客公开商品提示。
- 老板可新增默认零权限的伙计，并从六项固定权限中勾选授权或停用；挂牌价、成本价和最低价按字段裁剪与写入鉴权，伙计不能自提权，老板记录不可被修改。
- 两个档口、每档口两个商品组、访客/多组客户/单客授权客户/无系数客户及三项价格的可重复合成种子；客户页可直接切换四种测试身份。
- 本地媒体含两张 SVG、一张 PNG 和 3 秒合成 MP4，不使用真实商品或他人版权素材。
- 停止 API 后用 `BACKUP_CONFIRM_OFFLINE=1 npm run backup` 联合备份 PostgreSQL 与本地媒体，失败时自动移除不完整目录；媒体源不能包含备份目标。`npm run restore -- backups/<时间>` 流式校验并预解压媒体后，以单事务恢复到显式确认的独立目标库；备份输入不能是链接，媒体目标及其父目录须留在项目内，且目标不能是当前 `MEDIA_ROOT`。

## 当前可执行检查

本机已验证 Node.js `v24.19.0`、npm `11.17.0`：

```sh
npm run check
```

该命令当前通过 14 个领域/媒体/请求边界/合成资产/备份恢复/微信构建配置测试、API TypeScript 静态检查及四份集成/运维脚本语法检查。依赖已安装，`package-lock.json` 已生成；PostgreSQL `16.15`、API、小程序构建和基础端到端集成均已在本机验证。

另已在不带 `node_modules`、`.env` 和构建产物的项目内临时副本中，用 npm 本地缓存执行 `npm ci --ignore-scripts --offline`，随后的 `check` 和 `miniapp:build` 均通过；临时副本已清理。

已安装 PostgreSQL 并创建本地开发库后，日常启动顺序：

```sh
npm ci --ignore-scripts
cp .env.example .env
npm run db:init
npm run db:seed
npm run api
npm run miniapp:build
# API 运行时另开终端
npm run test:integration
```

`DATABASE_URL` 指向的数据库及角色须事先存在。API 就绪检查为 `curl http://127.0.0.1:3000/health`；小程序构建目录为 `apps/miniapp/dist/build/mp-weixin`。拿到自有 AppID 后用 `WECHAT_APPID='wx<16位十六进制值>' npm run miniapp:build:wechat` 只修改忽略提交的构建产物，不在源码保存 AppID。修改 API 源码后需重启 `npm run api`。详细版本、PostgreSQL 启停、备份恢复、审计风险和微信开发者工具步骤见 [环境与复现](docs/05-environment.md)。

## 业务边界

- 微信真实登录和手机号授权尚未接入；`DEMO_MODE=1` 的测试身份只允许在非生产环境使用。
- 交易与收款在线下进行；当前不实现支付、担保、分账、公开商城、品质结论、自动群发、标签系统、盘点或应收。
- 服务端授权只能限制后续访问，不能阻止截图、翻拍或客户转述价格。
- 媒体上传/审核与客户授权管理已实现，但扩展集成脚本因当前执行沙箱禁止 PostgreSQL 连接和共享内存尚未实跑；微信开发者工具因 `touristappid` 不存在而未完成导入/真机。
- 上次成功的 npm 生产依赖审计有 32 项（11 high，无 critical），均来自当前 DCloud/uni-app 兼容依赖树；本次复核受 registry DNS 阻断。不能使用会降级 DCloud 包的 `audit fix --force`，上线前须升级到官方修复组合并回归。
